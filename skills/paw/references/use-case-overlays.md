# Initial project overlays

Load only the profile that matches project evidence. These prompts identify
fields to assess; they are not defaults to copy blindly.

## Existing LaTeX teaching tree

Record:

- course, term, audience, and primary language;
- roots for notes, slides, exercise lists, exams, solutions, figures, and
  bibliographies;
- controlling source when local Git, Overleaf, Drive, or another mirror
  coexist;
- required engines, bibliography tools, fonts, shell-escape needs, and
  representative build targets;
- public versus restricted teaching material;
- notation, theorem, exercise, and solution conventions;
- generated PDF locations and cleanup rules;
- relevant MAW teaching, LaTeX, Quarto, and review capabilities.

Prefer a thin overlay. Do not reorganize a large working tree merely to match a
generic MAW scaffold.

## Unorganized Stata/R research project

Record:

- raw, intermediate, derived, output, manuscript, log, and scratch locations;
- which data are immutable, sensitive, restricted, or externally controlled;
- discovered `.do`, `.ado`, `.R`, `.Rmd`, `.qmd`, and project environment
  files;
- candidate entry points and their evidence, without inventing an execution
  order;
- Stata version and packages, R version and environment, seeds, and expected
  logs;
- source authority for manuscripts, data dictionaries, and idea sketches;
- estimands, sample rules, inference choices, and disclosure checks when
  established;
- unresolved dependencies and reproducibility gaps.

Treat initial organization as an inventory and proposed overlay. Moving data,
renaming scripts, or constructing a pipeline requires a separate approved
plan.

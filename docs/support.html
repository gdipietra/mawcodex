Documentation and reporting

Support

Start with the evidence you have. Do not turn missing runtimes, inaccessible files, or blocked permissions into a vague “it does not work.”

Install and update

Use the repository's installation guide. Preview the local marketplace plan before applying it, review hooks before trust, and begin a new Codex thread after an updated installation.

Use a capability

Browse the capability ledger, then invoke the relevant skill by name or describe the academic task naturally. Project instructions and authority remain controlling.

Report a bug

Open a GitHub bug report for reproducible public defects. Search existing issues first.

Contribute

Read the contribution guide. Conversion changes need provenance, semantic review, structural validation, and representative forward tests where behavior is high risk.

A useful bug report includes

  • MAW Codex version and installation source.
  • Operating system, Codex surface, and relevant external runtime versions.
  • The exact skill or command and the smallest safe reproduction.
  • Expected behavior and observed behavior.
  • Redacted logs, file paths, or screenshots that locate the failure.
  • A clear statement of what passed, failed, or remained UNVERIFIED.

Never attach credentials, raw restricted data, student records, answer keys, confidential manuscripts, private correspondence, or enclave-protected output to a public issue.

Security reports

Destructive-command bypasses, unsafe overwrites, credential or data exposure, unintended external actions, and misleading sandbox claims are security relevant. Use a private GitHub security advisory when enabled. If no private route is available, open a minimal public issue asking for a private contact path without disclosing the exploit or sensitive material.

See the repository security policy.

Scope boundaries

Support can diagnose package behavior and improve documented workflows. It cannot provide institutional clearance, legal advice, journal acceptance, restricted-data release approval, or guaranteed scientific validity. Optional R, Stata, Python, LaTeX, Quarto, browser, and connector behavior must be tested in the target environment.

Attribution corrections

Provenance errors are release-integrity defects. Open an issue with the affected file, the authoritative source, and the specific correction. Do not remove existing notices while a licensing question is unresolved.

Original MAW Codex contribution

The workflow gained a project control plane.

Pedro's source supplies the academic execution system. MAW Codex adds a separate management layer for adoption, ownership, personalization, instruction hierarchy, updates, and sanitized learning across ongoing projects.

Native agent

ManageRAW

Coordinates the management layer without absorbing its component skills. It routes work among JAW, CAW, PAW, LAW, UAW, and SAW and records shared decisions in the MAW project profile.

Boundary: it cannot alter global instructions, merge same-named skills, infer another plugin's private behavior, or authorize external actions.

JAW - Join

Assess before adoption.

Maps project history, source authority, protected material, dependencies, collisions, and rollback before any MAW state is written.

Boundary: assessment-only is the default; environment changes and integration require separate approval.

CAW - Coordinate

Make ownership explicit.

Assigns each step to MAW, project-local instructions, a specialist plugin, or a connector without inventing global precedence.

Boundary: unavailable capabilities and unresolved material choices remain UNVERIFIED or return to the user.

PAW - Personalize

Separate shared from personal.

Maintains tracked team choices in .maw/profile.yaml and non-weakening machine choices in ignored .maw/local.yaml.

Boundary: it does not infer source authority, data sensitivity, build order, or publication rights.

LAW - Layer

Build the instruction graph.

Designs root and nested AGENTS.md, supported project configuration, and effective precedence for concrete target paths.

Boundary: inaccessible global or project instructions make precedence UNVERIFIED, never assumed.

UAW - Update

Reconcile, do not overwrite.

Compares the old MAW base, project overlay, and candidate base so updates preserve project decisions and external ownership.

Boundary: explicit-only; discovery, plan, apply, install, and external actions are separate gates.

SAW - Slice

Learn without leaking.

Creates evidence-bounded project-return or generalized upstream-learning slices from recorded state.

Boundary: secrets, data, students, unpublished content, code bodies, absolute paths, and external-plugin settings are excluded.

Academic safeguards

Unknown is a state, not an inconvenience.

Scientific validity, reproducibility, confidentiality, and provenance outrank speed. Missing tools, inaccessible sources, skipped renders, and unexecuted analyses remain UNVERIFIED.

Evidence vocabulary

PASS requires observed evidence. FAIL identifies a violated gate. UNVERIFIED preserves a missing runtime, source, permission, or human decision without laundering it into confidence.

External-action boundary

Commit, push, deployment, submission, email, upload, sharing, synchronization, and deletion are separate actions. A workflow name never silently authorizes them.

Protected material

Raw and restricted data remain immutable or controlled. Outputs face disclosure checks. Answer keys, student data, unpublished work, and credentials are never promoted into public artifacts by default.

Auditable conversion

Every migrated component has a fixed source path and hash, a conversion classification, a revision record, structural validation, and forward testing when behavior is complex or high risk.

Release 1.2.2

Local readiness and publication are different claims.

The package can be locally release-ready before GitHub exists. Remote CI, a live Pages deployment, a GitHub Release, and a marketplace listing each need their own observed evidence.

1. Validate Run the fixed-source contract, official plugin and skill validators, hooks, unit tests, provenance, and stable evidence.
2. Publish with authority Create the repository, review the exact Git actions, enable Pages via GitHub Actions, and wait for both workflows.
3. Inspect live Verify the URL, links, responsive layout, credits, legal pages, install path, and release artifacts before saying “published.”
